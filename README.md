# 資金の温度計

時価総額上位20銘柄の動きと、今どこにお金が流れているかを1時間ごとに集計して、Webのダッシュボードで表示するツールです。GitHub Actions（データ集め）と GitHub Pages（表示）だけで動くので、サーバー代はかかりません。

## 見ているもの

| 指標 | 取得元 | 意味 |
|---|---|---|
| ステーブルコイン残高の7日変化 | DefiLlama | 実需のお金がそのチェーンに入ってきているか |
| DEX出来高の7日変化 | DefiLlama | 実際に取引が活発になっているか |
| TVLの7日変化 | DefiLlama | DeFiに預けられているお金の増減 |
| 建玉(OI)の24時間変化 | Hyperliquid（無い銘柄はBinance→OKX） | レバレッジのお金がどれだけ入ったか |
| 資金調達率(FR) | Hyperliquid（無い銘柄はBinance→OKX） | ロングが混みすぎていないか |
| セクター時価総額の対BTC | CoinGecko | 上位銘柄が属するセクター（ソラナ系・AI系・ミーム系など）の勢い |
| 価格トレンド（7日線・30日線） | Binance（ダメならOKX）の4時間足 | 上昇の流れに乗っているか、落ちている最中か |
| OIと価格のズレ | 上の2つから計算 | 新しい買いで上がっているのか、OIだけ膨らんで危ないのか |
| 今の資金の流れ | 上の指標から計算 | 上位銘柄のBTC比と時価総額の増減、資金が向かっている／抜けているセクター |
| 取引できるトークン | DefiLlama + CoinGecko + Hyperliquid + Ostium | チェーンの通貨のカードに出す、各チェーンのDeFiトークン・エコシステム銘柄のうち、Hyperliquid か Ostium で取引できるもの（出来高順） |
| 上位20銘柄のカード | CoinGecko + Hyperliquid + Binance/OKX + DefiLlama | 銘柄ごとの状態（出遅れ候補・初動・トレンド中・過熱など）と理由、BTC比、出来高、FR、OI、トレンド、OIと価格のズレ、関連セクター。チェーンの通貨ならチェーンの温度も |

状態が「出遅れ候補・初動・トレンド中」で、「上昇トレンド」＋「OIに危ないズレなし」がそろった銘柄のうち、上から最大3つに **◎ 条件そろい** が付きます。エントリーを検討する候補の目安です。

## 今の資金の流れ

ページの一番上に、上位銘柄を24時間のBTC比で並べた棒グラフと、ひとことのまとめ（「BTCより強いのは SOL・SUI。資金はSolana Ecosystemに向かっています」など）を出します。
BTC比+1%以上を「強い」、-1%以下を「抜けている」とし（`FLOW_MOVE`）、上位銘柄が属するセクターのうち初動・トレンド中・過熱のものを「資金が向かっているセクター」、失速・弱いものを「抜けているセクター」として最大3つずつ出します（`FLOW_SECS`）。

## 上位20銘柄の読み方

監視するのは**時価総額20位まで**の銘柄です（BTC・ステーブル・ラップ系は除外。`TOP_RANK`で変更可）。
銘柄ごとに、属しているセクター（BNB Chain Ecosystem、Meme、RWAなど）の局面と、銘柄自身の動きを見て「いまの状態」をつけます。

- **出遅れ候補**: 関連セクターがBTC比+3%以上動いて初動かトレンド中なのに、その銘柄はまだ追いついておらず、FRも低い
- **初動 / トレンド中**: 銘柄自身がBTCより強い
- **過熱・追わない**: 24時間でBTC比+8%以上か、FRが0.05%以上
- **様子見 / 失速 / 弱い**: 方向が出ていない、または資金が抜けている

カードはこの状態の良い順に並びます。各カードには、BTC比（24時間・7日）、出来高、FR、OIの24時間変化、価格トレンド（7日線・30日線）、OIと価格のズレ、関連セクターの局面と、48時間の価格の線が出ます。
ETH・SOL・BNBのようにチェーンの通貨であれば、そのチェーンの温度（ステーブルコイン・DEX出来高・TVLの7日変化）と、そのチェーンで取引できるトークンも同じカードに出します。
「Layer 1」「Ethereum Ecosystem」のような広すぎるカテゴリは、資金の回り先が分からないので関連セクターとしては使いません（`EXCLUDE_CAT`）。Hyperliquidにある銘柄は、名前をタップすると取引画面が開きます。

## セットアップ（15分くらい）

1. **CoinGeckoのDemo APIキーを取る**
   coingecko.com でアカウントを作り、Developer Dashboard から Demo キーを発行します（無料）。

2. **GitHubにリポジトリを作ってファイルを置く**
   このフォルダの中身をそのまま push します。

3. **キーをSecretsに登録する**
   リポジトリの Settings → Secrets and variables → Actions → New repository secret
   名前: `COINGECKO_API_KEY` / 値: 手順1のキー
   ※キーはコードやチャットに直接貼らないでください。

4. **GitHub Pagesを有効にする**
   Settings → Pages → Source を「Deploy from a branch」、Branch を `main` と `/docs` にして保存します。

5. **初回のデータ取得を手動で動かす**
   Actions タブ → `update-data` → Run workflow。
   成功すると `docs/data.json` がコミットされ、Pagesの URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）で表示されます。以降は毎時自動で更新されます。

## 手元で見た目を確認する

```bash
pip install -r requirements.txt
python scripts/fetch_data.py --mock      # サンプルデータを作る
python -m http.server -d docs 8000
# ブラウザで http://localhost:8000/?mock を開く
```

本番データで試す場合は `COINGECKO_API_KEY=xxxx python scripts/fetch_data.py` を実行します。

## 知っておいてほしいこと

- **先物データ**: まず Hyperliquid の公開APIから取ります。Hyperliquid に無い銘柄だけ Binance → OKX を試します（GitHub Actions はアメリカのサーバーなので Binance はブロックされがちです）。どれもダメなときは FR と OI なしで計算し、画面に警告を出します。価格トレンドは Binance → OKX の4時間足から取ります。
- **建玉の24時間変化**: Hyperliquid は現在の建玉しか返さないので、このツールが毎時保存した値と比べます。この版に更新してから24時間後に表示されます。
- **銘柄のセクター情報**: CoinGecko から少しずつ（1回の更新で最大10銘柄、週1で取り直し）取るので、全銘柄が埋まるまで3〜4時間かかります。その間は画面に警告が出ます。取った情報は `cache/coin_meta.json` に保存されます。
- **履歴は溜まるほど賢くなる**: セクターの7日変化と48時間の価格の線は、このツール自身が貯めた履歴から計算します。セクターの7日変化は、動かし始めて7日後から使われます。
- **Actionsの遅延と停止**: スケジュール実行は混雑時に数分〜十数分遅れることがあります。また、リポジトリに60日間動きがないと GitHub がスケジュールを止めることがあるので、止まっていたら Actions タブから再開してください。
- **状態とスコアは目安**: どれもBTCとの比較やチェーン同士の順位なので、全体が下げ相場でも「相対的にマシな所」が上に来ます。

## カスタマイズ

`scripts/fetch_data.py` の上の方で変えられます。

- `CHAINS`: 監視するチェーンと先物銘柄の組み合わせ
- `WEIGHTS`: 各指標の重み
- `FR_HOT` / `FR_CALM` / `OI_HOT`: 「過熱気味」「静かに流入中」の判定ライン
- `MIN_CAT_MCAP` / `MAX_CATS`: 見るセクターの最低時価総額と件数
- `PX_MOVE` / `OI_MOVE` / `OI_SURGE`: OIと価格のズレを判定するライン
- `TOKENS_PER_CHAIN` / `TOKEN_MIN_TVL` / `TOKEN_SHARE`: 取引できるトークンの件数と拾う条件
- `OSTIUM_FALLBACK`: Ostium の銘柄一覧が取れなかったときに使うリスト
- `TOP_RANK`: 監視する時価総額の順位（初期値20）
- `COIN_ENTRY_MAX`: 「条件そろい」を付ける銘柄の最大数
- `FLOW_MOVE` / `FLOW_SECS`: 「今の資金の流れ」で強い／抜けているとするBTC比と、出すセクターの数
- `LAG_MIN_SECTOR`: 「出遅れ候補」にするのに必要なセクターの動き（初期値BTC比+3%）
- `EXCLUDE_CAT`: 関連セクターとして使わないカテゴリ名のキーワード
- `PHASES`: 銘柄の関連セクターの局面の表示名

チェーン名は DefiLlama の表記に合わせる必要があります（見つからないものはログに `skip` と出ます）。
